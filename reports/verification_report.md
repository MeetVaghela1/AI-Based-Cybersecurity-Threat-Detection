## 3. Retroactive leakage check

1. **Preprocessor refit.** A fresh `Preprocessor` was fitted on the pre-SMOTE training split of each dataset and its parameters compared with the saved preprocessor: median imputer statistics, min-max scaler bounds (`scale_`, `min_`), one-hot categories and output feature names all **match exactly** for both datasets. Because the steps are deterministic, this proves the saved preprocessor was fitted on exactly this training data.
2. **SMOTE placement.** Every one of the 8 saved models is a pipeline `[('smote', SMOTE), ('clf', <estimator>)]` — SMOTE is an *in-pipeline* step that `GridSearchCV` re-fits inside each cross-validation fold on the fold's training portion only. It is never applied to the test split.
3. **Test split purity.** The saved test pickles contain **only real raw rows**: their class counts equal the raw test class counts exactly (NSL-KDD: 9,711 Normal / 7,458 DoS / 2,887 R2L / 2,421 Probe / 67 U2R; CICIDS2017: 3,000 DDoS / 3,000 PortScan / 3,000 DoS / 3,000 Normal / 2,767 Brute Force / 436 Web Attack / 394 Botnet / 7 Infiltration / 2 Heartbleed).
4. **Scaler bounds.** The MinMaxScaler maps the *training* range exactly onto [0,1] for every column, while the scaled test matrix falls outside [0,1] on many columns — direct evidence the scaler was fitted on the train split only, never on the test split.

## 5. Conclusions

- **All saved processed artifacts match a from-scratch re-derivation exactly** (cell-level equality for every matrix, identical class distributions, identical shapes).
- **No data leakage found.** Preprocessors were fit on training data only; SMOTE lives inside the CV folds; test splits contain real raw rows only.
